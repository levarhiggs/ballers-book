# Baller's Book

An offline iPad app (installable web app) for showing animated basketball plays at practice.
Each play is a single self-contained HTML page, usually built as a Claude artifact, behind a
home screen. No accounts, no backend, and no network after the first install.

Live at **https://levarhiggs.github.io/ballers-book/** (after the first deploy below).

## What's here

```
index.html               home screen (cards come from plays.json)
plays.json               the play list: one entry per play
plays/                   one HTML page per play (+ zone-layouts.default.js)
shared/shell.css|js      top bar (Back, Lock, Keep awake, Fullscreen), iPad layout, sound setting
shared/version.js        version shown on the home screen
sw.js                    service worker: caches everything for offline use
manifest.webmanifest     app name/icons for "Add to Home Screen"
icons/                   generated by tools/make_icons.py
tools/                   add/check/bump scripts and the Playwright test harness
```

`source-plays/`, `exported layouts/` and the original spec text are **gitignored**. The
original Zone Shift Studio has real player names in it, so it stays on this PC only.

## Run it locally

```
cd playbook
python -m http.server 8000
```

Open http://localhost:8000. Offline mode works on `localhost`. In Chrome DevTools, go to
Application > Service Workers, tick **Offline**, and reload. The home screen pill should
read **Offline ready**.

## Deploy (GitHub Pages, no Actions)

One-time setup:

1. `gh repo create ballers-book --public --source . --push`
   (or create the repo on github.com, then `git remote add origin …` and `git push -u origin main`).
2. On github.com, go to the repo's **Settings > Pages**, set Source to **Deploy from a
   branch**, Branch **main**, folder **/ (root)**, and click Save.
3. After about a minute the app is live at https://levarhiggs.github.io/ballers-book/.

Every later deploy: `python tools/bump.py`, commit, `git push`.

## Install on the iPad

1. Open the URL in **Safari** (not Chrome), then tap **Share > Add to Home Screen**.
2. Launch it from the home screen **on Wi-Fi** and wait for **Offline ready** on the home screen.
3. Test it: turn on airplane mode, close the app fully (swipe it away), reopen it and run each play.

Saved data (zone layouts, player names, settings) belongs to the home-screen app. Safari
keeps it separately, so data saved in a Safari tab won't appear in the app, and the other
way round. Always edit inside the home-screen app.

## Updating the app

1. Make the change, then run `python tools/bump.py` (it updates `sw.js` and `shared/version.js` together).
2. `python tools/check.py`, commit, `git push`.
3. On the iPad, open the app on Wi-Fi. The home screen shows **Update ready**; tap **Update**
   and check that the version number changed. (Fully closing and reopening the app also applies it.)

If you skip the version bump, iPads keep running the old cached copy.

## Adding a play

Export the play from Claude as a single HTML file, save it in `source-plays/`, then:

```
python tools/add_play.py source-plays/my-play.html --category Offense --description "One line for the card."
```

This copies it into `plays/`, adds the shell lines (head and `<body>` tag only; the
play's own code isn't changed), adds a `plays.json` entry, bumps the version and runs the
checks. Optionally add a `"thumb"` to its entry for a mini-court preview (copy the shape of
an existing one: `frame` is the play's court bounds, `dots` the five players, `ball` the
ball). Test locally, then commit and push.

Plays laid out like Inbound Stack and GGP (a `.wrap` holding a `.court` with an SVG) get the
landscape layout automatically. A play with a `#bSnd` button or `#snd` checkbox follows
the app-wide sound setting.

## Zone Shift Studio

- **Default layouts.** On first run, a device with no saved layouts loads yours
  (`plays/zone-layouts.default.js`, from your 2-3 export; it also has the 3-2 spots you
  edited). To change the defaults, use **Export / import > Show current layouts**, paste
  the text over `DEFAULTS` in that file, bump the version and deploy. Devices that already
  have saved layouts keep their own.
- **Moving layouts from the Claude artifact.** The artifact's saved layouts can't carry over
  automatically (different website). In the artifact, use **Show current layouts** and copy
  the text. In the app, open **Export / import**, paste it and tap **Load from text**.
- **Back up layouts.** This copies the layouts to the clipboard and opens the share sheet
  (choose **Save to Files**). **Restore from file…** loads a backup. Back up before big edits.
- **Player names.** Open **Player names (saved on this iPad only)** and type names. They're
  stored on that device only, never in the app's code, the repo or a backup. Without names,
  defenders show their numbers.
- **Lock.** The top-bar **Lock** hides the edit, reset and import controls and stops
  defenders from being dragged, so a stray tap at practice can't change anything. The ball,
  tours and double-tap spotlight still work. Tap **Locked** to unlock.
- **Reset all spots** asks for confirmation first.

## Tests and checks

All run against the local server, started from `playbook/` with `python -m http.server 8765 --bind 127.0.0.1`.
Playwright is installed globally, so prefix each node command with `NODE_PATH="$(npm root -g)"`.

| Command | What it proves |
|---|---|
| `python tools/check.py` | every play listed and present, shell tags in place, versions match, no external URLs, payload size |
| `node tools/baseline.js source-plays orig` then `node tools/baseline.js plays new`, then `python tools/compare.py orig new` | plays behave exactly like the originals: every button, Switch/mirror, Cycle loop, with seeded randomness |
| `node tools/offline_test.js --update` | installs, goes offline, opens and runs every play, then tests the Update flow |
| `node tools/zone_test.js` | defaults, lock, names, backup/restore, Reset-all confirmation, touch drag, sound shared across plays, keep-awake setting |
| `node tools/shots.js label` | screenshots at iPad landscape/portrait and phone sizes, light and dark, in `tools/out/` |

Expected `compare.py` result: identical, except that the zone-imported run's first step
reflects your default layouts loading on first run.

**Name guard.** `tools/hooks/pre-commit` blocks any commit that contains a player name from the
local original. Git doesn't copy hooks, so on a new clone run `cp tools/hooks/pre-commit .git/hooks/`.

## Checklist for the real iPad

These can't be fully proven on a PC:

- [ ] Installs from Safari, launches without browser chrome, correct icon and name
- [ ] **Offline ready**, then works in airplane mode after closing and reopening the app
- [ ] Zone Shift Studio: dragging defenders and the ball by finger feels right, and the page doesn't scroll while dragging
- [ ] Sound plays after the first tap; turning it off in one play keeps it off in the others
- [ ] Screen stays awake on a play page (iPadOS 16.4+; wake lock in home-screen apps needs 18.4+)
- [ ] Landscape: court large and readable from a few feet away; portrait still fine
- [ ] Back up layouts, Save to Files, then Restore from file round-trips
- [ ] After a deploy: Update ready, then Update, and the new version number shows
